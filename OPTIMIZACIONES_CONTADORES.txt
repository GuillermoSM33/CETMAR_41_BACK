   └─ Retorna: {"male": 10, "female": 7}
6. get_students_by_regularity()                  ← Query 6 ✅ (Regular + Irregular juntos)
   └─ Retorna: {"regular": 15, "irregular": 2}
7. get_students_by_career()                      ← Query 7
8. get_registered_users_count()                  ← Query 8
9. get_active_events_count()                     ← Query 9
10. get_uploaded_report_cards_count()            ← Query 10

BENEFICIOS:
  ✅ 50% menos queries (12 → 6)
  ✅ GROUP BY reduce procesamiento en BD
  ✅ Una sola lectura de identities para género y regularidad
  ✅ Menor latencia de red
  ✅ Menor uso de CPU en BD


═══════════════════════════════════════════════════════════════════════════════
COMPARACIÓN SQL: ANTES vs DESPUÉS
═══════════════════════════════════════════════════════════════════════════════

ANTES (2 queries separadas):
─────────────────────────────
SELECT COUNT(*) FROM identities WHERE Gender = 'M';
SELECT COUNT(*) FROM identities WHERE Gender = 'F';

Problemas:
  • 2 full scans de identities
  • 2 network round-trips
  • Datos duplicados procesados


DESPUÉS (1 query optimizada):
───────────────────────────
SELECT Gender, COUNT(*) FROM identities 
WHERE Gender IS NOT NULL 
GROUP BY Gender;

Beneficios:
  • 1 scan de identities
  • 1 network round-trip
  • GROUP BY agrega en BD
  • Retorna 2 filas (M, F)
